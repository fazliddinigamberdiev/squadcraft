# SquadCraft (TransferMind)

Smart football squad audit and transfer management tool. ISE4133 Software Engineering team project.

**Team:** Rakhmatullaev Umid, Abdullaev Umrbek, Igamberdiev Fazliddin

SquadCraft lets a club manager or sporting director pick one of the 96 clubs in the 2026/27 Premier League, Serie A, LaLiga, Bundesliga or Ligue 1 (or build a squad from scratch), audit the squad, and get transfer and free-agent suggestions that fit the manager's playstyle and budget.

## Architecture

```
browser (index.html + app.js + config.js)  --HTTPS/JSON-->  Supabase (PostgREST)  -->  PostgreSQL
 draws screens, sends requests only                          tables, RLS, views, SQL functions = all data and all rules
```

- **The database is the backend.** Clubs, players, free agents, playstyles, user squads and every rule (thin depth, upgrade/future-proof ranking, free-agent scoring, offload matching) live in Supabase as tables, views and SQL functions. `app.js` contains no player data and no business rules. See `db/schema.sql`.
- **No build step, no server.** Static files; the page calls `/rest/v1/...` and `/rest/v1/rpc/<function>`.
- **Your own squads, no login.** On first visit the browser creates a random *access key* (UUID, stored in `localStorage`) and sends it in the `x-owner-token` header. Row Level Security only shows rows whose `owner_token` equals that header, so each visitor sees and edits only their own squads. The footer has **Copy access key / Use access key** to open the same squads on another device. Anyone who knows your key can open your squads, so treat it like a password.
- **Workspace model.** Opening a club copies its squad into your private workspace (`rosters` + `roster_players`). You can add, edit, remove, injure players, change playstyle, window state and budget; everything is saved in the database. Limits: 20 squads per key, 60 players per squad.

## Run it

1. Clone the repository and open `index.html` in a modern browser (needs internet access).
2. `config.js` holds the public Supabase URL and anon key (safe to publish; data is protected by RLS). To use your own Supabase project, run the SQL files below in the SQL editor and change `config.js`.
3. Free Supabase projects pause after a week of inactivity. If the page says it cannot reach the database, restore the project in the Supabase dashboard.

### Database setup (new project)

Run in this order (SQL editor, or `psql`):

1. `db/schema.sql` - tables, constraints, indexes, RLS policies, views, functions, grants
2. `db/seed/reference.sql` - leagues, positions, playstyles, data sources, 96 clubs
3. `db/seed/load_data.sql` - 2,382 players and 154 free agents (generated by `node db/seed/build_seed.js` from `db/seed/data.js`)
4. `db/seed/simulated_squads.sql`, then `select fn_seed_simulated_squads();` - 328 made-up players for the 14 promoted clubs

## Club logos

Each club has a `logo_url` in the database (`logos/<club id>.png`). The page shows that image and falls back to a colored code badge when the file is missing. The files are downloaded once with `tools/fetch_logos_apifootball.js` (needs a free API-Football key in the `APIFOOTBALL_KEY` environment variable, never committed) or `tools/fetch_logos.js` (Wikidata). Crests are trademarks of their clubs and are used here only for a non-commercial course project.

## Features and the rules behind them

| Tab | What it does | SQL function |
|---|---|---|
| Squad Audit | KPIs; all 8 position groups with player count, **Thin depth** badge when a group has fewer than 2 players; sortable roster with flags (expiring contract <= 2027, aging >= 31, prospect, style mismatch); add/edit/remove/injure players | `fn_workspace_overview`, `fn_workspace_depth`, `fn_workspace_kpis`, `fn_workspace_roster` |
| Recruitment | **Immediate Upgrade**: players rated strictly above your current (non-injured) starter at the position, optional fee cap and league, sorted by rating, then style fit, then potential. **Future-Proof**: age <= limit (default 21) and market value <= fee (inclusive). Empty results show the database message ("No candidates match these limits" / "No player rates above the current starter"). "Add to squad" copies a target into your squad. | `fn_recommend_upgrade`, `fn_recommend_future`, `fn_add_from_database` |
| Emergency Free Agents | Unattached players for the position of an injured player (or weakest position), ranked by `rating*1.5 + fit*0.6 - |rating - target|*0.8`; wage, over-32 and verified-only filters; "Sign" adds them to your squad. | `fn_emergency` |
| Offload Planner | Players with style fit < 60 (young prospects excluded) and up to 3 buyer clubs whose style fits better, whose budget covers the value, and that need the position. | `fn_offload` |

Other functions: `fn_search_clubs` (club search), `fn_create_workspace`, `fn_style_fit`, `fn_owner_token`.

## Data and limitations

- **Real squads:** 82 clubs (2,382 players) from the open [transfermarkt-datasets](https://github.com/dcaribou/transfermarkt-datasets) project, snapshot **6 July 2026**.
- **Free agents:** 154 players. 138 verified from transfertracker.ai (22 Oct 2026). 16 were reported as unattached in news (2-4 Sep 2026) and are labelled "verify" in the UI.
- **Simulated data:** the 14 newly promoted clubs have **simulated** squads (328 made-up players generated inside the database, same result every time). They are marked "sim" in the UI.
- **Estimates:** ratings, potential, playstyle attributes and wages are SquadCraft model estimates, not official figures. Contract end is a year only, so "expiring" means 2027 or earlier; a missing year is treated as 2027.
- **Privacy:** no accounts and no personal data. Squads are stored in Supabase under a random access key. The page no longer loads Google Fonts (system fonts are used).

## Tests

`tests/smoke.js` loads the real `index.html`, `config.js` and `app.js` in jsdom with a mocked database and checks that the club grid, thin-depth alerts, recruitment lists, free agents and offload planner render from database responses.

```bash
cd tests && npm install && npm test
```

The SQL rules were also verified directly in PostgreSQL (see the midterm/final report) by running the functions on real squads.

## Differences from M1/M2

The M1 vision and M2 story slice are in `docs/`. The final app follows them, with these differences:

| M1/M2 said | Final app |
|---|---|
| "Live" valuations and real-time data (M1 Assumption 3, high confidence) | The data is a snapshot: the open dataset is current to 6 July 2026 and its maintainer paused updates. The club of 310 players who moved in summer 2026 was updated from API-Football (free plan, 100 requests a day). Injuries are set by the user, not read from a feed. Players who left for clubs outside our 96 are not removed, and new signings are not added. |
| "Position-specific performance rating (0-100) from mock data" (S2-AC1) | `est_rating` (1-99) is a SquadCraft estimate from market value and age, not match performance. The UI says "estimates". The data is real players, not mock data. |
| Prototype without a custom backend, live API or full player database (M1) | The scope grew on purpose: a Supabase database with 96 clubs, about 2,700 players, row-level security and SQL functions for every rule. |
| Offloader and Emergency Free Agent Finder deferred (M2) | Both are built (`fn_offload`, `fn_emergency`), with the wage filter from the M1 critique. |
| Negotiation simulation excluded | Still excluded. |
| Immediate Upgrade has no fee limit; Future-Proof uses the fee typed by the user | Same, plus an option (on by default) to cap both lists at the squad's transfer budget. Untick it to use only the typed fees. |
| User check: 3-5 analysts, more than 75% of recommendations plausible (M1) | Not done. We make no claim that the recommendations are verified by users. Only the rules were checked, in SQL and in `tests/smoke.js`. |
| M2 reviewer names and tick boxes | Not filled in yet (they need a team member). |

## Known issues / not started

- Data is a snapshot; there is no refresh pipeline.
- Estimated ratings and playstyle fit are not validated against real scouting data.
- Anonymous access keys: no password recovery; losing the key means losing access to those squads.
- No automated accessibility or mobile testing yet.
